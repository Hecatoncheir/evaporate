# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Evaporate — десктопный лончер игр на Flutter (macOS / Linux / Windows): библиотека,
встроенный BitTorrent-клиент и перенос сохранений между устройствами. Каталога
контента в приложении нет — источник каждой игры задаёт пользователь.

## Команды

```bash
flutter pub get   # обязателен первым: он же генерирует lib/l10n/app_localizations*.dart
flutter test
flutter test test/save_manager_test.dart      # один файл
flutter test --plain-name 'метка правила'     # один тест или группа по имени
flutter run -d macos
```

Сгенерированные `lib/l10n/app_localizations*.dart` не в репозитории, и
**неявный `pub get` внутри `flutter test` их не создаёт** — на свежем клоне без
явного `flutter pub get` (или `flutter gen-l10n`) всё, что импортирует
локализацию, не соберётся. То же после правки `.arb`.

Перед отправкой правки — ровно то, что гоняет CI (`.github/workflows/ci.yml`):

```bash
dart format --output=none --set-exit-if-changed lib test
flutter analyze
flutter test
```

**Анализатор считает провалом и подсказки (info), не только ошибки.** Смотрите
весь его вывод, а не отфильтрованный по слову `error`.

Прочее:

```bash
python3 tool/make_icon.py        # перерисовать иконки (png, .ico, набор для macOS)
python3 tool/fetch_manifest.py   # положить настоящий манифест Ludusavi в third_party/
flutter build macos --release    # linux / windows аналогично
```

Тесты не требуют ни сети, ни геймпада, ни собранного приложения. Часть
пропускается по платформе (реестр — только на Windows, `.app` — только на
macOS), это норма: **прогон идёт на всех трёх системах**, поэтому пропущенное
здесь выполняется там. `ludusavi_manifest_bench_test.dart` пропускается без
скачанного манифеста.

CI: `analyze` (формат и анализатор, ubuntu) и `test` — матрица из ubuntu,
macOS и Windows с `fail-fast: false`. Покрытие снимается один раз, на ubuntu,
и уходит в сводку прогона и в артефакт `coverage-<sha>`. Локально то же:
`flutter test --coverage` кладёт `coverage/lcov.info`.

Версия Flutter зафиксирована в `env.FLUTTER_VERSION` (3.47.2, Dart 3.13.2).
Сборки трёх платформ идут только на теге `v*` либо ручным `workflow_dispatch`;
на теге же архивы прикладываются к релизу и берут артефакты по маске
`evaporate-*` — иначе к релизу уехал бы и отчёт о покрытии. Выпуск версии —
правка `version:` в `pubspec.yaml`, запись в `CHANGELOG.md` (Keep a Changelog,
semver) и тег.

## Язык

Комментарии, документация, `CHANGELOG` и сообщения коммитов — по-русски.
Комментарий объясняет **почему**, а не что; хороший отвечает на «почему не
проще?». Тест называется утверждением о поведении («свежий прогресс не
затирается старым пакетом»), а не именем метода.

Все видимые строки живут в `lib/l10n/app_ru.arb` (исходник) и `app_en.arb`
(обязателен). Тесты-стражи в `test/localization_test.dart` сверяют наборы
ключей, подстановки и обходят `lib/ui` в поисках кириллицы в строковых
литералах — при срабатывании строку выносят в ARB, а не глушат проверку.

Исключение помечено в коде: `label` у моделей, действий и состояний движка и
функции в `lib/core/format.dart` остаются русскими намеренно — они идут в
журналы. Переводимые подписи для показа собраны в `lib/ui/labels.dart`, потому
что у моделей и слоя ввода нет `BuildContext`.

**`SavePathRule.defaultLabel` («Сохранения») не переводится.** По метке правила
сопоставляются между устройствами: переведись она, снимок с русской машины
перестал бы сходиться с правилом на английской. Хранится как есть, переводится
только показ (`ruleLabelText`).

## Состояние: Bloc с событиями

Четыре блока: `SettingsBloc`, `LibraryBloc`, `DownloadsBloc`, `NavigationBloc`.
Каждый — папка `lib/bloc/<feature>/` из трёх файлов (события, состояние,
обработчики), связанных через `part`. Состояния иммутабельны (`Equatable`),
у `SettingsBloc` состояние — сам `AppSettings`.

Событийная модель здесь не церемония: **внешние источники подают события
наравне с нажатиями пользователя**. Лаунчер сообщает о завершении процесса
через `GameExited`, движок загрузок — через `EngineTasksChanged`,
`EngineStatusChanged`, `EngineStatsChanged`, каталог путей — через
`SavePathsProgressChanged`.

Асинхронные операции не пробрасывают исключения в виджеты:

- ключи выполняющихся операций лежат в `state.busy` (`state.isBusy(...)`) —
  собственный `bool _busy` в экранах не нужен;
- результат кладётся в одноразовый `Notice`, а единственный `BlocListener` в
  `AppShell` показывает его SnackBar'ом. У `Notice` есть счётчик `seq`: без него
  два одинаковых сообщения подряд считались бы одним состоянием.

Событие ничего не возвращает — отсюда пара мест, выглядящих странно: диалог
добавления игры сам генерирует id и передаёт его в `GameAdded`, а перед стартом
загрузки дожидается появления игры в состоянии, иначе два блока разошлись бы в
порядке обработки.

`flutter_bloc` построен на `provider`, поэтому оба используются по назначению:
блоки раздаёт `BlocProvider`, сервисы без состояния (`GamepadService`,
`NotificationService`) — обычный `Provider`.

Порядок в `main.dart` важен: настройки читаются до создания остальных блоков
(они нужны им в конструкторе), окно ставится до показа, значок в трее ставится
всегда. Язык блоки получают функцией `L Function()` — `BuildContext` у них нет,
а язык может смениться на ходу; по умолчанию `LRu()`.

## Перенос сохранений — суть приложения

`lib/core/save_path_template.dart`: в профиле игры хранится **не абсолютный
путь, а шаблон** — `{APPSUPPORT}/MyGame/Saves`. На другой машине и другой ОС тот
же шаблон разворачивается в правильный локальный путь (`expand`/`collapse`).
`{GAME}` — папка установки игры, самый частый случай; её знает только тот, кто
знает, о какой игре речь.

`.evsave` — обычный zip: `manifest.json` (метаданные и правила) плюс
`data/<ruleId>/...`. При восстановлении правила сопоставляются сначала по id,
затем **по метке** — так снимок с Windows ложится в macOS-путь той же игры.
Версия формата лежит в `manifest['format']`, а читаемые версии перечислены в
`SaveSnapshot.readableFormats` — множество, а не сравнение с текущей: пакеты
переживают версии приложения, и проверка на равенство означала бы, что новая
сборка не читает ничего снятого раньше. Добавляя версию, старую не убирают.
Формат читают чужие сборки на других устройствах: несовместимое изменение рвёт
то, ради чего всё затевалось, и обсуждается до правки. Пакеты приходят извне,
поэтому при распаковке проверяется выход за пределы целевой папки (zip-slip).

Массовая загрузка сравнивает время снятия пакета с временем изменения сейвов и
пропускает игры, где это устройство ушло вперёд (допуск две минуты на расхождение
часов). Восстановление всегда сначала снимает резервную копию.

Откуда берутся пути:

- `LudusaviCatalog` — открытая база путей (манифест Ludusavi, MIT). Качается по
  требованию, лежит в кэше приложения, **разбирается в отдельном изоляте**:
  десятки тысяч записей заморозили бы интерфейс на секунды. В репозиторий и
  сборку не входит.
- `SaveActivityWatch` — то, что база не знает (торрент-релизы, всё мимо Steam):
  после выхода из игры смотрит, что изменилось за время её работы. Отбор по
  нескольким признакам сразу, известные кэши и логи отбрасываются по имени.
  Результат — **предложение человеку, а не запись молча**.
- `SavePathFinder` — поиск по названию игры в типичных местах. Тоже догадка.

Перенос всей библиотеки разом живёт в `BulkTransfer` (`lib/services/saves/`), а
не в блоке: на входе список игр, на выходе `BulkResult` с отчётом и строкой
сообщения, поэтому цену переезда можно проверить, не поднимая ни блока, ни
состояния. Готовые снимки отдаются колбэком `onSnapshot` — список должен
пополняться на глазах, выгрузка большой библиотеки идёт минуты.

Ветки реестра Windows база знает; переносить их приложение не умеет, но
сообщает о них — иначе снимок вышел бы неполным без единого слова.

## Загрузки

`DownloadEngine` — узкий контракт, `DtorrentEngine` — единственная реализация
(`dtorrent_task_v2`, чистый Dart, внешнего бинарника нет). Выбран ради SOCKS5:
через него идёт и обмен с пирами (`useForPeers: true`), тогда как aria2 SOCKS не
поддерживает вовсе. Смена прокси перезапускает активные задачи.

Имена времён aria2 из кода убраны, и осталось от них ровно одно, намеренно:
`Game.fromJson` читает старый ключ `downloadGid` наравне с `downloadTaskId` —
библиотеки, записанные до переименования, лежат у людей на дисках. Ветку
прикрывает тест в `library_bloc_test.dart`; удалять её нельзя, пока такие
библиотеки живы.

## Ввод: клавиатура и геймпад — один словарь

`NavAction` (`lib/input/nav_action.dart`) — единый набор действий; и клавиши, и
кнопки контроллера сводятся к нему, дальше по приложению идёт только `NavAction`.
`InputScope` в оболочке добавляет недостающие `Shortcuts`/`Actions` и мостит
поток геймпада. `DirectionalFocusIntent` перехвачен намеренно: штатный
обработчик не умеет стартовать с пустого фокуса. Раскладка живёт в настройках,
применяет её `GamepadService`.

## Оформление

`EvaporatePalette.dark` / `.light` в `lib/ui/theme.dart`; цвета раздаются через
расширение темы (`context.colors.textSecondary`), а не константами — иначе две
схемы не сосуществовали бы. `test/theme_test.dart` меряет контраст каждого цвета
на каждой подложке и требует WCAG (4.5 для подписей, 7 для основного текста);
часть палитры отклонена от исходных значений именно им. Шрифты вшиты в сборку и
вариативные — `test/fonts_test.dart` проверяет, что они слушаются `fontWeight`,
по ширине набранной строки.

Правило уведомлений: **SnackBar — для того, что пользователь только что нажал
сам; системное уведомление — для того, что закончилось в фоне** (загрузка
завершена, загрузка сорвалась, автоснимок после выхода из игры не удался). Об
ошибке загрузки уведомляем один раз — на переходе в состояние, а не на каждом
опросе движка.

## Тесты

`test/support/test_app.dart` собирает всё приложение с подменённым потоком
геймпада. Две ловушки записаны там же в комментариях: `TestHarness` **обязан**
создаваться внутри `testWidgets` (Bloc запоминает зону подписки, и блок из
`setUp` доставлял бы события мимо фейкового времени), а временная папка,
наоборот, готовится снаружи — настоящий файловый I/O внутри `testWidgets` не
завершается никогда. По той же причине `saveRoots: () => const []`: обход
настоящих «Документов» не закончится.

Правка, меняющая поведение, идёт с тестом; правка, исправляющая ошибку, — с
тестом, который без неё падает.

## Что обсуждать до правки

Новый экран, замена зависимости, смена формата `.evsave` — сначала issue.
Формат снимков особенно: его читают чужие сборки на других устройствах.
